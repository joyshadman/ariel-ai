# Architecture Context

## Stack

| Layer     | Technology                              | Role |
| --------- | --------------------------------------- | ---- |
| Framework | Next.js 16.4 (App Router, RSC, Turbopack) | Serves UI + API routes; `cacheComponents` + `partialPrefetching` on |
| UI        | React 19 + Tailwind CSS v4              | Hand-rolled components, dark zinc theme |
| Language  | TypeScript (strict)                      | Whole codebase |
| AI        | Vercel AI SDK v7 + provider SDKs        | Streaming chat; **BYOK** — user key used at request time |
| Database  | Neon Postgres + Prisma 7                | User/keys/chats/messages; Neon serverless driver |
| Auth      | Supabase Auth (`@supabase/ssr`)         | Email/password sessions, cookie-based |
| Tests     | Vitest (unit) + Playwright (e2e)        | `npx prisma generate` output is `lib/generated/prisma` |

## System Boundaries

- `app/api/` — Route handlers. Auth + ownership check before any read/write.
  `/api/chat` streams; `/api/keys`, `/api/chats`, `/api/chats/[id]` are JSON.
- `app/` — Pages and layouts. `(auth)` group = landing/guest pages,
  `(app)` group = authed pages (dashboard, chat, settings}. `proxy.ts` guards them.
- `lib/` — Server-side shared code: `db.ts` (Prisma), `crypto.ts` (AES-256-GCM),
  `supabase/` (server + browser clients), `auth/dal.ts` (auth+db user helpers),
  `ai/types.ts` (client-safe provider constants) and `ai/providers.ts`
  (server-only: real provider model factory).
- `lib/generated/prisma/` — Generated Prisma client. Never edit by hand;
  regenerate with `npx prisma generate`.
- `prisma/` — `schema.prisma` (models) + `prisma.config.ts` (datasource URL,
  migrations).
- `proxy.ts` — Next 16 middleware replacement (session refresh + route guards).
- `tests/` — Vitest unit tests + `tests/mocks/server-only.ts` (mock for tests).
- `e2e/` — Playwright specs (directory created; first spec not yet written).
- `context/` — Product/architecture/standards/progress docs agents must read.
- `.opencode/` — opencode agents, commands, skills configuration.

## Storage Model

- **Postgres (Neon + Prisma)**: all product data:
  - `User` — one row per auth user (id matches Supabase user id, unique email).
  - `ApiKey` — one per `(userId, provider)`; stores ciphertext/iv/authTag of the
    key (AES-256-GCM) plus `lastFour`, optional `label`.
  - `Chat` — per user, auto-title from first user message.
  - `Message` — `role` ("user"/"assistant") and `parts` (JSON) per chat.
  - `CreditLedger` — reserved for the deferred credits system. Not used yet.
- Secrets (provider keys) live only in the DB, encrypted. `.env` holds app-level
  secrets (encryption secret, Supabase, DATABASE_URL).

## Auth and Access Model

- Every user signs in via Supabase Auth (email/password, SSR cookies).
- `getAuthUser()` reads the session; `getDbUser()`/`getDbUserOrNull()` resolve
  the matching `User` row, upserting it on demand. Route handlers must use
  `getDbUserOrNull()` (no `redirect()`).
- Ownership: chats, API keys, messages are scoped by `userId`. Mutations verify
  `chat.userId === dbUser.id` before writing/returning.

## Invariants

1. Provider keys are always stored encrypted and decrypted only at request time
   for the provider the user selected. Never logged, never returned to the client.
2. Every route handler enforces auth then ownership before any mutation.
3. Server-only secrets/DB code stays out of client components — `lib/ai/types.ts`
   is the only client-safe import surface; `lib/ai/providers.ts` is `server-only`.
4. `npm run lint` and `npm run build` must pass before work is considered done.
5. The `<!-- BEGIN:nextjs-agent-rules -->` block in AGENTS.md is regenerated by
   `next dev` — never remove it permanently.

## Monetization (deferred)

Credits + optional monthly purchases via bKash (Bangladesh) come later. When
built, BYOK usage must not be double-billed: never charge credits for inference
a user already pays for through their own key. `CreditLedger` is the eventual
accounting table.
